# TODO登録と関連メモ

## 登録フォームの整理（2026-11-27）

- 必須はタイトルのみ。冒頭で「やることだけで登録できます」と案内する。
- 関連メモのあとに繰り返し・ルーティンの設定をまとめ、日時・通知より先に表示する。
- ルーティンONで直下に毎日・平日・毎週・毎月を表示。間隔を選ぶまでは登録を無効化し、同じ場所で必要な操作を案内する。バックエンドの既存チェックは維持する。
- 通常の繰り返しTODOとルーティンの区別は維持。ルーティンOFFにしても選んだ繰り返しを勝手に消さない。
- 間隔を手動で選んだ場合はタイトルの自動解析より優先する。未選択なら従来どおり解析結果を使用する。
- 日時・通知は詳細の外。「取り組む時刻」と詳細内の「かかる時間」を区別し、通知日・時刻にはラベルを付ける。
- 詳細は分類・優先度・見積・期限・ナビ。各項目に用途説明を付け、編集でも開閉できる。閉じても入力値・既存データは保持する。
- 設定行は文字を縮小せず、折り返し・高さと余白で収める。保存形式・通知処理・Premium条件は変更しない。
- `qa-task-form-clarity.test.js` と本番Appの回帰テストで、3テーマ・間隔選択・入力のみ登録・通知・編集・保存/再起動を確認する。
- 検証結果：全Jest 38 suites・338件PASS（今回のフォーム回帰9件追加）、型チェック・iOS向けJS export・diffチェックPASS。
- Reactチェックで、設定行をmodule直下の部品へまとめ、入力中のstateを保持。文字の自動縮小は使わず、主項目15pt・折り返し・余白で収める。
- iPhone実機で小画面・文字拡大・キーボード表示中のスクロール・DateTimePickerを最終確認する。commit・pushは未実施。

2026-11-27：サブタスクとリスト・メモに分かれていた入力を、既存の関連メモへ統一。

- TaskModalのタイトル入力の下に「関連メモ」を表示。詳細設定を開かずに追加できる。
- 新規項目は既存の`Task.listItems`へ保存する。HomeScreenの「今」の関連メモ欄、リスト・メモ編集、Widgetチェックリスト、Live Activityの既存経路を利用する。
- メモのチェックは親TODOの完了・完了取消を実行しない。メモはTODO件数にも加算しない。
- 通常のTODO編集でもメモを表示・編集・並べ替え・削除できる。キャンセルでは保存しない。
- 入力途中で外部からメモがチェック・追加・削除された場合、`mergeTaskMemoEdit`が最新状態を保持する。親Taskの他フィールドは従来の最新refに対して更新する。

## 旧サブタスクの互換性

`taskWithUnifiedMemos`をAppの読込・追加・更新の入口で使う。低レベルの`loadRhythmState`自体は読み取り専用のまま。

- 正常な`subtasks`を`listItems`へ引き継ぎ、文章・done→checked・順番・未知の項目フィールドを保持する。
- 既存メモと同名でも統合しない。IDが衝突した場合は旧手順側のIDに決定的な接頭辞を付け、どちらも残す。
- 引継ぎ後の`subtasks`は空配列。再読込・再実行で項目を追加しない。保存キー・ルート形式・既存メモ形式は変えない。
- 入力が部分破損している場合は勝手に削除・変換せず元のTaskを保持する。その破損データの復旧UIは今回追加していない。
- 引継ぎはまずメモリ上で行い、永続化は既存の全体snapshot保存キューを通す。保存失敗時は従来の未保存表示・保存再試行を使用し、旧保存データは保持される。
- 完了済み親TODOや他のTODO、Wishとのorigin、写真参照を変更しない。
- 旧形式を直接扱う低レベル関数は互換性のため残しており、今回のApp経路では正規化後のTaskを使用する。
