# iCloud state sync — Phase C

- `resolveSyncDecision` is pure whole-state last-write-wins. Invalid body/meta/hash are rejected, newer empty remotes cannot replace populated local data, and drafts/unsaved changes defer adoption. Equal timestamps keep local. No item-level merge.
- `syncCodec` uses pinned JS-only `@noble/hashes@1.8.0` for SHA-256. Optional `bodyHash` was approved by the owner for sync metadata only; new uploads include it and downloads require it. Unhashed legacy snapshots are never adopted. Metro resolves only noble's browser crypto shim, not Node crypto; no Native crypto dependency/polyfill was added.
- `useICloudStateSync` checks after hydration, on KVS events and activation. The coordinator holds uploads until initial comparison and separates hydration normalization/rebasing from real edits, preserving the source timestamp to prevent ping-pong. Other tabs/internal forms conservatively wait for safe Home or next startup. Home sheets, root editors, focus, selection mode, keyboard and one-second interaction grace are protected.
- Local writes keep the existing serial queue and notify outside it. Remote adoption is conditional work in that SAME queue: compare disk/version, backup one generation, recheck view/version/remote, then write. Input during a Native write rolls back before later local jobs. Existing hydrationRetry reloads. Backup failure never writes main state; IO failures log and retain the backup.
- Sync-only local keys: `rhythm-sync-device-id-v1` (existing), `rhythm-state-local-sync-meta-v1` (new timestamp + hash), `rhythm-state-pre-sync-backup-v1` (raw backup; literal null means no previous state). Missing/mismatched local metadata on first Phase C launch conservatively favors existing local data. Hash mismatch detects a crash between state and metadata writes.
- Strict read failures are not confused with missing cloud state. Stable meta/body/meta reads, byte count and hash bind a snapshot. KVS is neither transactional nor immediate.
- Upload keeps 3-second debounce, 900,000-byte cap, durable ID and warning-only failure/next-save retry. UI-cancelled jobs can be rescheduled. No unbounded retry loop. The optional Native adapter remains the only platform boundary.
- Missing managed photos are display-filtered only. Stored URI/crop remain. Cleanup is file-side only and protects startup/current/one-generation backup references. Photo files are NOT synchronized.

Details, protocol migration, tests, Apple signing steps, device procedures and limitations: `docs/icloud-phase-c.md`. Historical Phase A/B reports remain unchanged. The owner's latest instruction authorizes commit/push after verification.
